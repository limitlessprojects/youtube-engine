## What worked

- **L-046 — The GitHub clone IS the workstation.** Sandbox loss costs ~2 minutes
  when (a) the token lives in `.secrets/` with `chmod 600`, (b) the repo is pushed
  after every milestone, (c) recovery is muscle memory: clone → identity → go.
  Refinement of L-044: the repo dir holds nothing that matters, only unpushed
  session state can hurt us — and session state is reconstructible because the
  ledger + logs carry enough context.
- **L-047 — Verify "dead" claims with a second egress before acting.** WebFetch's
  fetcher reported oEmbed "Not Found" for a LIVE video (fetcher artifact); curl
  seconds later returned the real title. One tool's artifact nearly caused us to
  retire a live queue item. Rule: any "this resource is gone" verdict gets a second
  opinion (curl vs WebFetch vs browser) before we mutate the queue.
- **L-048 — Dead-ID triage belongs in the loop, and oEmbed is the oracle.** It works
  from cloud IPs (not behind the captions bot-wall), returns title/channel for free,
  and a 404 is *proof of death* — no proxy ladder ever fixes a dead ID. Wired into
  `transcribe.py` (pre-check + `DeadID` + exit code 4) and `daily_loop.py` (pops +
  logs RETIRED). 9tbxDgcv74c-style multi-day retries of corpses are now impossible.
- **L-049 — POT infrastructure ≠ bot-wall ticket on a hard-flagged IP.** bgutil's
  own README says it: a PO token "may help your traffic seem more legitimate".
  On an IP already serving Google sorry-pages and 429s, nothing helps. Keep the
  infra (cheap, permanent, works on marginal IPs), but don't burn session time
  re-testing clients on the same flagged exit — rotate the exit or wait.
- **L-050 — Mirror ecosystems decay in days; query live registries, never hardcode.**
  All 6 default Invidious mirrors + 8 Piped mirrors dead. The instance registries
  themselves are fetchable JSON — the tool already accepts `INVIDIOUS_INSTANCES` /
  `PIPED_INSTANCES` env overrides, so the next run feeds it fresh lists (and CI can
  do the same per-leg).

## Addendum (same day, boss strategy session): bootstrap + RSS + honest egress audit

Boss asked: "what difficulties is this AI facing and what solution would you suggest?"
Answered with a ranked table (sandbox volatility, hard-flagged egress, mirror decay,
API quota blackouts, aggregator Turnstile walls) and shipped four of the proposed
fixes the same session:

- **L-051 — The bootstrap manifest kills sandbox volatility.** `bootstrap.sh` (repo
  root) is the ONE command a fresh session runs: python deps + yt-dlp + bgutil
  plugin (check-before-install), git identity, token perms (mirrors the project-level
  `.secrets/gh_token` into the repo, which is gitignored), shallow submodule init for
  only what's missing, optional POT server start, `--ci`/`--whisper` flags. Now also
  the CI install step ("Bootstrap" replaces raw `pip install` in both jobs) — one
  source of env truth, local and CI.
- **L-052 — WebFetch's "Html Convert Error" means REACHABLE but unrenderable JSON.**
  Same signature on pipedapi.kavin.rocks and instances.cobalt.best — the fetcher
  reaches the host, its HTML converter chokes on JSON. Treat that string as a liveness
  signal and re-route through curl/browser, never as "site down".
- **L-053 — Channel RSS feeds are the discovery oracle: no bot-wall, view counts
  included.** `youtube.com/feeds/videos.xml?channel_id=UC…` served from CDN caching,
  works from the hard-flagged IP, carries videoId/title/published/description AND
  `media:statistics@views` — the outlier rule (views ÷ channel average) computes
  from RSS alone. Shipped `tools/rss_scout.py` (handle→id resolution cached,
  niche-title regex, `--enqueue N`, wired into daily_loop's empty-queue branch in
  BOTH local and CI-merge modes). First run: 6 outliers ≥ 2x across all 4 benchmark
  channels; `What If We Cool Down the Sun?` flagged niche. This retires the
  bot-walled `yt-dlp ytsearch` discovery path.
- **L-054 — Cobalt for YouTube is a dead end in 2026 (documented, move on).** Official
  cobalt.tools blocked by YouTube since 2025; community instances: 1 of 19 probed
  alive (`cblt.fariz.dev`, v11.7.1) and it requires an API key (`auth.key.missing`);
  the 2024 scraping-abuse crackdown keyed or killed the rest; self-hosting on a
  GitHub runner = same bot-wall. Cobalt returns media, not captions, so even a win
  would need whisper. CLOSED unless boss provisions a VPS/edge egress (a $2-5/mo
  Railway/Fly cobalt instance with its own IP would work; needs their account).
- **CI ladder widened to 5 legs** (direct/proxy/android/mweb/tv) with per-leg
  player-client mapping via `fromJSON` — client diversity only pays on fresh runner
  IPs (L-049), so it lives in CI, not in local retries. Merge priority updated to
  match.
